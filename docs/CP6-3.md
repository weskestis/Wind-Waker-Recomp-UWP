# CP6.3 — explicit Xbox render-device binding

CP6.1 and CP6.2 launched safely on the physical Xbox Series X, but no audible
tone reached the output. CP6.2 confirmed XAudio2 source samples were advancing,
so the failure is now treated as an output-routing problem rather than a source
voice or buffer problem.

CP6.3 keeps Dawn completely excluded and changes the mastering path.

## Device routing

The UWP host resolves the default render device with:

`Windows.Media.Devices.MediaDevice.GetDefaultAudioRenderId(AudioDeviceRole.Default)`

Microsoft documents that API as returning the identifier of the current default
audio render device.

That exact device ID is passed to `IXAudio2::CreateMasteringVoice` instead of
passing a null/default device pointer.

The mastering voice is forced to:

- 2 channels
- 48 kHz
- `AudioCategory_GameEffects`

The source voice also runs at 48 kHz stereo.

## Runtime diagnostics

The app records in LocalSettings:

- whether a default render-device ID was resolved
- the resolved device ID
- mastering voice channel count
- mastering voice input sample rate
- overall explicit-device audio probe result

The existing two-note test and `SamplesPlayed > 0` verification remain active.

## Result meaning

- dark blue/black + audible tone: explicit XAudio2 routing works
- gray: device resolution, mastering voice creation, or sample playback failed
- dark blue/black but still silent: XAudio2 is processing audio on the selected
  Xbox device but is not reaching audible output; the next backend will be the
  UWP-native `Windows.Media.Audio.AudioGraph` path

The executable still has no `webgpu_dawn.dll` startup dependency.
