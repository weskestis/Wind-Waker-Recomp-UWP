# CP6.4 — UWP AudioGraph device-output backend

CP6.0 crashed because the desktop prebuilt Dawn DLL was linked into the Xbox
process. CP6.1 through CP6.3 restored stable launch and proved that XAudio2 was
processing samples, including on an explicitly selected Xbox render device, but
no audible output reached the physical Series X.

CP6.4 removes XAudio2 from the build and switches to the UWP-native
`Windows.Media.Audio.AudioGraph` pipeline used by Microsoft's UWP audio
samples.

## Graph

The Xbox host creates:

`AudioGraph -> AudioFrameInputNode -> AudioDeviceOutputNode`

The graph is configured with:

- `AudioRenderCategory.GameEffects`
- system-default quantum sizing
- the UWP default render device as `PrimaryRenderDevice`
- the output format selected by the platform audio graph

## PCM feed

The host subscribes to `AudioFrameInputNode.QuantumStarted`. Whenever the
platform requests samples, the app creates an `AudioFrame`, locks its memory,
fills float PCM samples, and submits the frame with `AddFrame`.

The current diagnostic signal is two seconds:

- first second: 660 Hz
- second second: 880 Hz

The tone amplitude is 0.55 float PCM with short fades.

This is intentionally the same frame-input architecture the eventual GXRuntime
audio sink can use. The game mixer can feed decoded stereo PCM into the
AudioFrameInputNode instead of SDL or XAudio2.

## Safety

CP6.4 retains all CP1-CP5 tests and CI fails if either of these process startup
dependencies reappear:

- `XAudio2_9.dll`
- `webgpu_dawn.dll`

## Expected Xbox result

- audible two-note tone + dark blue/black: AudioGraph device output works
- gray: graph creation, device-output creation, or frame-feed initialization failed
- hold A: green controller confirmation

If CP6.4 is audible, this becomes the permanent Xbox audio backend.
