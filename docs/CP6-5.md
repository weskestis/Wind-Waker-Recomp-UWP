# CP6.5 — staged manual AudioGraph diagnosis

CP6.4 crashed at launch on the physical Xbox Series X. CP5 remains the last
fully known-good checkpoint.

CP6.5 does not initialize any audio API during startup. It launches as the
known-good CP5 host and only touches AudioGraph after the user presses B.

Each B press advances exactly one stage:

1. enumerate/resolve the default render device
2. create AudioGraph
3. create AudioDeviceOutputNode
4. create/connect AudioFrameInputNode and queue a prepared two-second tone
5. start the graph and frame-input node

The two-second tone is 660 Hz followed by 880 Hz.

Before each stage begins, the app records the attempted stage in LocalSettings.
After a successful stage it records the completed stage. If a stage crashes the
process, the next launch detects attempt > completed and displays a unique
crash-stage color before any audio API is touched again.

## Normal stage colors

- stage 0: dark blue/black — untouched CP5
- stage 1: dark blue/cyan
- stage 2: purple
- stage 3: orange/brown
- stage 4: gray
- stage 5: teal/greenish — graph started

## Crash-stage colors on the next launch

- crash in stage 1: bright cyan
- crash in stage 2: bright purple
- crash in stage 3: bright orange
- crash in stage 4: white
- crash in stage 5: bright mint/green

A plain red audio screen means a stage returned failure without crashing.

Hold A still forces the normal green controller confirmation.

CI rejects both webgpu_dawn.dll and XAudio2_9.dll startup dependencies.
